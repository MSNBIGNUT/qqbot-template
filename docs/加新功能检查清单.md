# 给春禾加新功能时的检查清单

> 由来：2026-10-20 真机事故 —— `web_search` / `web_fetch` 注册好几天了，
> 但**能力清单里没写**，于是主人问她能不能联网时，她诚恳地回答「我没有这个能力」。
> 同一天又发现 `stay_silent` 也有同样的问题。
>
> **教训**：她的自我认知来自 `describeCapabilitiesForModel()` 这份清单，
> 不来自工具列表。**工具给了却不写清单 = 她不知道自己会用。**

---

## 加一个「工具类」功能（她能主动调用的）

按顺序做，**每一步都别跳**：

### 1. 定义工具
```js
export const MY_TOOL_NAME = "my_tool"   // ← 全小写下划线
export const MY_TOOLS = [{ type: "function", function: { name: MY_TOOL_NAME, ... } }]
```

**工具描述里必须写清三件事**：
- 什么时候用（具体场景，不要"根据需要"这种空话）
- 什么时候**不该**用
- 做不到时怎么办（**"如实说"而不是"编一个"**）

### 2. 注册到工具列表
在 `src/persona/chunhe.js` 的 `generate()` 里，按开关 push 进 `tools`：
```js
if (on(config.myFeatureEnabled)) tools.push(...MY_TOOLS)
```
**没开就不注册** —— 和「没 key 不注册画图」同一个原则。

### 3. ⚠️ 写进能力清单（最容易漏的一步）
在 `describeCapabilitiesForModel()` 里加一条：
```js
lines.push(
  on(config.myFeatureEnabled)
    ? "· **XXX**：能……。做不到时如实说。"
    : "· **XXX**：现在关着——要如实说没开。"
)
```
**关着时也要有一条**，否则她分不清"没开"和"没有"。

### 4. 加进覆盖表
`test/tool-coverage.test.js` 里的 `TOOL_TO_CAPABILITY` 加一行：
```js
{ tool: MY_TOOL_NAME, keywords: ['XXX'], configFlag: 'myFeatureEnabled' },
```
**漏了这行 CI 会红，并告诉你缺哪个工具。**

### 5. 处理工具调用
在 `generate()` 的工具分发里 await 真实结果，**失败原因原样回填给模型**：
```js
const result = { ok, content: "成功了…" /* 或 */ "失败了：<原因>。（如实说，不要编）" }
```
回填的文案要**带"不要编"的提醒** —— 模型会照着这段话说话。

### 6. 配置开关
- `src/config.js` 加字段
- `.env.example` 加一行 + 注释

### 7. 测试
- 逻辑测试（离线，注入假依赖）
- 工具定义测试（名称/描述/必填参数）

## 反面案例（真实发生过）

| 事故 | 表象 | 根因 |
|---|---|---|
| 联网工具 | 她：「我没有联网工具，系统清单里也没有这一项」 | 工具注册了，`describeCapabilitiesForModel` 没写 |
| 沉默权 | 她每条都接话，从不"不回" | `stay_silent` 注册了，清单没写 |

**两次都不是崩溃，而是她会一直诚恳地说错话 —— 只有主人主动问才会暴露。**

---

## 一条原则

> **她能做什么，由那份清单决定，不由工具列表决定。**
>
> 加工具 = 同时改三处：**工具定义 + 注册 + 能力清单**。
> 少一处，她就"不会用"或"不知道自己会用"。
